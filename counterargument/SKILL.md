# Counterargument

Help the user test their position against strong alternatives. Work directly in chat, in the user's language. This is a read-only discussion; file output or implementation changes require an explicit request.

## 1. Identify the claim

Use the user's named position, or the position they are defending in the current discussion. Restate its strongest reasonable version, including its objective and constraints, in one or two sentences. Ask which claim to challenge only when the conversation supplies none.

Separate factual claims from priorities and preferences: evidence can contradict a prediction, while a competing priority exposes a tradeoff.

Completion: the claim being challenged is recognizable as the user's position, not a stronger or weaker substitute.

## 2. Build distinct opposing cases

Choose two or three relevant perspectives with genuinely different objectives, assumptions, or affected interests. Use the user's requested perspectives when provided. Merge perspectives that produce the same objection; relevance takes precedence over filling a quota.

For each case, establish:

- What this perspective prioritizes.
- Its strongest objection to the actual claim.
- The evidence or concrete scenario supporting that objection; label assumptions and unresolved facts.
- A viable alternative and the cost it introduces.
- A condition or observation that would make this objection matter less or overturn it.

Inspect supplied sources and directly relevant project material when the argument depends on them. Ground factual objections in evidence; conditional scenarios remain conditional. Judge defensible arguments by their strength rather than making every side appear equally persuasive.

Use the current model by default. Independent models are optional when requested; perspectives generated by one model are not independent reviewers.

Completion: each retained case challenges a different part of the decision and has a concrete basis and a condition under which it weakens. If no strong objection survives, say the claim withstood the available challenge.

## 3. Discuss the decision

Present the claim briefly, then the opposing cases, strongest first. Keep each case concise and distinguish contradictions of fact from differences in values or priorities.

Close with the single tension or unresolved question most likely to change the user's decision. Leave the judgment with the user rather than automatically adopting the opposing position.

In follow-up turns, respond to the user's rebuttal: withdraw defeated objections, strengthen surviving ones with evidence, or identify the remaining tradeoff. Update the discussion instead of restarting the same list.

Completion: the user can see the strongest opposing cases, what they depend on, and what would resolve the disagreement. Agreement is a valid outcome.
