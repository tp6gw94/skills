# Idea phase

## Purpose
Turn a request into a shared problem statement.
Make the intended user value and scope concrete before solution detail.

## Inputs
- The user request, observed pain, and supplied evidence.
- Known constraints, existing behavior, and explicit non-goals.
- If earlier material is missing, use the requirements, code, and evidence actually supplied.

## Deliverable
Record concise cards in the current phase source and same-page workbook HTML:
- **Problem:** whose problem exists and what is failing or costly.
- **User:** the affected actor or audience.
- **Value:** the outcome that would matter to that user.
- **Scope:** what is in and out for this work.
- **Testable assumptions:** each uncertain claim has a way to check it.
State the current decision, supporting evidence, and unknowns. This reference is guidance, not a standalone document or generated checklist.

## Completion
The reader can state the problem, user, value, scope, and how assumptions will be tested.
The phase shows a clear decision, evidence, and unknowns without pretending uncertainty is resolved.
Progress still needs explicit chat approval; content alone does not approve a phase.

## Boundary
Separate facts, assumptions, and requests for decision. Ask only about blockers.
Do not invent approval, add a feature, require a full-repository read, or force an interview.
